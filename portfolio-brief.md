### Section 2: Featured Case Studies

#### Case Study 1: Prodily — Product Management Academy
- **Elevator Pitch**: A structured learning platform helping aspiring product managers learn concepts through organized modules and individual lessons.
- **Category**: Educational Product / Web Application
- **Context & Problem**: Product management knowledge is fragmented across scattered articles, videos, and guides. Learners struggle without a cohesive, progressive curriculum.
- **Role & Ownership**: End-to-end product concept, information architecture, curriculum design, and technical implementation. Built using Next.js and TypeScript.
- **Key Decisions & Trade-offs**:
  - *Static Structured Lessons vs. Generative AI*: Chose a structured curriculum with static, curated content over AI-generated lessons to ensure predictable quality, easier review, and pedagogical consistency.
  - *Information Architecture*: Designed self-contained modules, clear progress tracking, and an intuitive dashboard to reduce cognitive load.
- **Deliverables & Evidence**:
  - Live platform: [https://prodily.adityagangwani.me](https://prodily.adityagangwani.me/)
  - 90 lessons organized across structured modules.
  - UI screenshots showcasing lesson viewer and curriculum dashboard.
- **Key PM Learning**: A learning product succeeds on curriculum structure, information hierarchy, and progress visibility—content alone is insufficient without a reliable, predictable delivery system.

#### Case Study 2: Featuresmith — Open-Source Python Library
- **Elevator Pitch**: A developer tool for dataset inspection, ML readiness assessment, data leakage detection, and dataset version comparison.
- **Category**: Developer Tooling / Open-Source ML Infrastructure
- **Context & Problem**: Preparing datasets for ML workflows involves repetitive manual validation. Silent issues such as data leakage or undocumented drift between versions frequently go unnoticed.
- **Role & Ownership**: Independent creator and product builder; managed feature roadmapping, implementation, testing, documentation, and version releases.
- **Key Decisions & Trade-offs**:
  - *Dual SDK & CLI Parity*: Built identical capabilities into both a Python API and a terminal CLI so engineers could integrate checks into pipelines or run ad-hoc audits.
  - *Modular Engine Architecture*: Progressively expanded the tool with modular sub-engines: Dataset Review Engine, ML Readiness Score, Leakage Detection, and Dataset Diff Engine.
- **Deliverables & Evidence**:
  - Open-source Python package with versioned releases.
  - Automated testing workflow with **66 passing unit tests (and 1 warning)** from local validation runs.
  - Public repository: `[needs input: GitHub repository URL]`
- **Key PM Learning**: Developer tools are evaluated on interface predictability, actionable terminal output, clear error messaging, and rigorous test coverage, not just raw algorithmic functionality.

#### Case Study 3: Operate — Open-Source Product Experience
- **Elevator Pitch**: A developer-focused product experience demonstrating how AI can assist software engineers in investigating issues and navigating unfamiliar codebases.
- **Category**: Developer Tools / Applied AI Exploration
- **Context & Problem**: Investigating software bugs in large codebases requires tedious manual navigation across unfamiliar dependencies and files.
- **Role & Ownership**: Product experience, presentation, user interaction flow, and visual direction for the open-source demonstration.
- **Key Decisions & Trade-offs**:
  - *Demonstration Fidelity vs. Production Claim*: Made a conscious product decision to frame the open-source release as a clear conceptual demonstration rather than claiming full parity with a verified production diagnostic system, setting accurate user expectations.
  - *Time-to-Value in UI*: Optimized the interactive flow so users can select an issue and immediately see how an AI-assisted investigation traces the codebase.
- **Deliverables & Evidence**:
  - Live interactive experience: [https://operatex.dev/open-source](https://operatex.dev/open-source)
  - Product website and visual assets.
- **Key PM Learning**: In developer tools, establishing trust early through honest expectation-setting, clear onboarding, and predictable outputs is vital to user adoption.

#### Case Study 4: Samsung PRISM — Troubleshoot Helper

## 5. Design Direction

### Tone & Character
- **Sleek, Modern, and Technically Credible**: Evokes the feeling of an early-stage technical product company (e.g., Linear, Vercel) rather than an entry-level student portfolio.
- **Product-Led, Evidence-First**: Prioritizes problem-solving narratives, architecture diagrams, and concrete outcomes over generic buzzwords or responsibility lists.
- **Restrained & Authentic**: Free of gimmicky animations, neon glow clutter, or exaggerated claims. Every design choice supports legibility and fast scanning.

### Reference Sites & Key Takeaways
1. **Linear ([linear.app](https://linear.app))**:
   - *Inspiration*: Precise typographic scale, crisp borders, dark subtle surfaces, structured feature cards with high information density, micro-interactions that feel snappy.
2. **Vercel ([vercel.com](https://vercel.com))**:
   - *Inspiration*: Monochrome palette, high-contrast typography, monospace accent details for technical metadata, clean grid layouts, minimal chrome.
3. **Personal Portfolio Guide ([adityagangwani.me/portfolio-guide](https://adityagangwani.me/portfolio-guide))**:
   - *Inspiration*: Retains Aditya’s authentic voice, structured case study hierarchy, and direct link structure while elevating visual execution.

### Visual Foundations
- **Color Palette**:
  - *Background*: Deep obsidian / carbon (`#0a0d12` or `#090a0f`) for dark mode; clean off-white (`#fbfbfd`) if light mode toggle is included.
  - *Surfaces & Borders*: Subtle translucent dark cards (`rgba(255, 255, 255, 0.04)`) with crisp borders (`rgba(255, 255, 255, 0.08)`).
  - *Accents*: Subtle electric cobalt or indigo (`#3b82f6` / `#4f46e5`) used sparingly for active states, link hovers, and status badges.
  - *Typography Colors*: High-contrast crisp white (`#f8fafc`) for headings, muted slate (`#94a3b8`) for body copy, and dimmed slate (`#64748b`) for metadata.
- **Typography**:
  - *Headings & Body*: Modern geometric sans-serif (e.g., `Inter`, `Geist Sans`, or `Plus Jakarta Sans`) with tight tracking on titles for a modern product aesthetic.
  - *Technical Metadata / Badges / Code*: Monospace font (e.g., `Geist Mono`, `JetBrains Mono`, or `Fira Code`) for metrics, test counts, Worklet IDs, and tool tags.
- **Layout & Structure**:
  - Generous horizontal whitespace (max width container: 1100px–1200px).
  - 2-column or asymmetric grid for case studies (context & decisions on the left; deliverables, interactive cards, and evidence on the right).
